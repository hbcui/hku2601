# 优先修复：执行图记忆与任务派发语义

> 历史实验：用户已明确 routing 为唯一 action，任务和车辆绑定作为外部输入。自主派发学习不再是当前方向；请以[当前条件协议](routing_only_external_conditions.md)为准。本文保留当时实现与失败记录。

更新：2026-11-15。实现入口为 `conditioned_world_model_executed_graph_v1`。这是执行语义修正实验，不是已晋升的长期预测模型；旧预测先验分支保留作失败对照。

## 两项主要修正

**记忆跟随实际生成分支。** 事件和运动执行后，用同一图编码器读取车辆、任务、资源关系，再结合实际位移、速度和计时器变化、任务变化、持有关系增减及实体出生更新记忆。编码使用当前关系图，不再只用 OHT 均值池化，也不让已有实体的记忆沿着脱离执行结果的特征预测器单独前进。输入是模型自己执行出来的状态；真实未来状态仍不进入自由推演。

零时长授权或分配也可以更新记忆；重复相同状态和零反馈不会反复制造更新。固定图下的物理时间滤波通过分段一致性测试。约束介入标志没有同等的原生事实标签，因此该通道不输入记忆；没有把“未知介入”伪装成事实零值。

**任务派发与资源时钟分开。** 资源保留连续事件率；任务不再出现在连续资源竞争集合中。批量任务在观察到的派发时刻形成一批分类决策：每个任务可选择合法车辆/操作或等待；已使用的车辆和任务槽不再重复使用。这是一个规范化、无放回的自回归匹配分布，不是固定最近车、强制启动或强制清空任务队列。

整个批次先在副本上通过现有硬执行器检查，再提交，任一动作失败不会留下部分分配。预分配任务的服务后自动提升仍由已有状态机执行，不等待下一次批量派发。

实现：[图记忆](../../src/conditioned_world_model_v4/executed_graph.py)、[派发时钟及匹配似然](../../src/conditioned_world_model_v4/batch_dispatch.py)、[运行时](../../src/conditioned_world_model_v4/runtime.py)。

## 派发相位来自观测，而不是整周期猜测

当前数据配置为 batch/5 秒，但 anchor frame 9000 的待执行队列给出的下一次派发约为 301.5667 秒，并非 300 或 305 秒。时钟从锚点已知 `pending_events` 初始化；推演不能借用后续真实检查点。缺少观测队列时拒绝默认为整周期相位。

数据标签对照已知时钟与原生有序 `task_lifecycle` 记录；从 CREATED 开始的派发与 PRE_ASSIGNED 的服务后提升分开处理。原生日志在下一帧末可见，因此标签保留 30 Hz 分辨率，不宣称恢复帧内所有回调顺序。同一时间的运行协议先处理到达边界的派发，再交付外部路线；复杂的同帧外部到达顺序仍需独立审计。

当前接口明确支持该 batch 环境契约；ASAP 或其他派发机制需要单独的时间协议，不能直接加载此检查点后静默更换。

## 训练与推演使用同一因果分解

1. 在派发前图上计算批次分类似然，模型看不到该批次的真实分配结果或由其产生的未来路线。
2. 训练时按真实批次结果更新账本并产生边界反馈，再学习其后的资源、运动条件分布；这是序列 teacher forcing。
3. 推演时按学习分布采样批次，通过同一个执行器提交，记忆读取自己产生的分配及后续执行结果。
4. 派发边界显式切分原有训练窗口；边界反馈与跨物理时间反馈分开保存。任务标签不再使用连续暴露时间。错用旧缓存或在连续任务标签上训练会被拒绝。

这修正了生成机制，不等于已经完成硬账本的多步可微训练。不能将原先孤立的冻结 OHT 特征目标直接套到新的执行记忆上，声称得到联合世界模型的多步似然。

数据工具见 [batch_data.py](../../src/conditioned_world_model_v4/batch_data.py) 和 [data.py](../../src/conditioned_world_model_v4/data.py)。检查点保存派发配置；评估核对数据配置。旧架构的执行语义不变。

## 本轮实际运行

新缓存使用训练 route seeds 0/1、验证 50、测试 59，frame 9000 起各 12 秒。每个窗口核对到 3 个派发机会、31 个原生分配，另保留资源和运动标签。总计只有 24 秒独立训练轨迹；这不是完整 50/5/5 或泛化验证。

模型从已有 generalized 检查点继承图与预测头，新增执行反馈和批次等待头；CPU 更新 40 次，按验证序列目标选第 40 次权重。验证目标从 9.156 降到 4.820，其中新增模块确实收到梯度。新目标包含批次分类项，不能与旧模型的验证总损失直接比较。

已完成的两个 20 秒闭环中，派发时刻均为约 301.5667、306.5667、311.5667、316.5667 秒，均无内部事件拒绝；现有记忆反馈日志也包含零时长执行更新。该结果确认机制连通，不能代替独立长期性能对照。

```bash
PYTHONPATH=src .venv/bin/python -m conditioned_world_model_v4.data \
  --execution-profile learned_hard_only_v1 --batch-dispatch --allow-shard \
  --train-seeds 0 1 --validation-seeds 50 --test-seeds 59 \
  --anchors 9000 --frames 360 --output runs/executed_graph_batch_v1/cache_new

PYTHONPATH=src .venv/bin/python -m conditioned_world_model_v4.train \
  --architecture conditioned_world_model_executed_graph_v1 \
  --init runs/generalized_hard_only_v2/factual_model/latest.pt \
  --cache runs/executed_graph_batch_v1/cache_new/cache.pt \
  --output runs/executed_graph_batch_v1/model_new --hidden 64 \
  --unroll-seconds 12 --context-seconds 2 --updates 40 \
  --validation-every 20 --lr .0001 --device cpu
```

## 仍需区分的边界

当前没有强制将真实路线绑定到模型预测任务，也没有补真实任务分配。不同任务分配导致后续真实路线不兼容仍是条件预测的风险，必须继续报告身份、时序及路线接受情况。该风险不能靠固定绑定规则掩盖。

旧访问状态分支微调器若不能提供真实执行反馈或派发时钟会显式拒绝运行；不能把其旧缓存直接当作本模型的闭环监督。正式性能评价仍需更多派发批次、独立轨迹和匹配环境契约的完整长闭环。

## 完成验证与限制

[验证汇总](../../runs/executed_graph_batch_v1/verification.json)：152 项模块测试、16 项安全投影测试通过。实际检查点恢复成功；两次 20 秒和一次 60 秒闭环完成，无状态重置、未来观测校正或内部事件拒绝。

seed 59 / frame 9000 的完整 60 秒记录中：

- 12 个派发机会均满足锚点队列给出的相位及 5 秒周期；每批 OHT、任务槽均无重复。
- 执行记忆收到 3,497 次反馈调用，其中 1,648 次为零时长调用。这是调用计数，不等于每次都产生非零记忆变化；相同图与零反馈的重复调用通过幂等性测试。
- 同一检查点与事件种子下，20 秒和 60 秒驱动的前 10 秒指标完全一致。这是已运行样本的非前瞻性检查，不是所有输入的证明。
- 60 秒位置 MAE 为 12.341 m，运动召回率 0.595，Merge 持有召回率 0.122。
- 新启动任务审计的匹配数为 0/126，模型生成了 121 个新启动任务对。数量接近不能代替车辆—任务身份和时序准确度。

因此状态仍为**机制修正已验证、预测质量未晋升**，默认模型没有改变。没有与不同派发契约的旧报告静默混排；比较工具现在会拒绝未声明的派发语义差异。正式任务分配质量、资源概率校准和跨场景表现尚未验证充分，不能把本次小规模训练写成长期模型已经完成。

# 50／5／5 联合训练运行协议

更新：2026-11-15。按用户明确要求扩大数据范围，采用当前资源—运动联合自动微分训练；此前先用 8 个种子的建议不再作为本次运行范围。扩大训练与长期性能验收是两件事。

## 固定配置

| 项目 | 本次配置 |
| --- | --- |
| 模型 | `conditioned_world_model_executed_routing_v1`，执行图记忆 |
| 训练方法 | 自身实际执行轨迹的 energy score + 概率回放自动微分；真实资源事件似然辅助项 |
| 初始化 | [已验证的 30 Hz 联合训练检查点](../../runs/executed_routing_v1/joint_autograd_clocked/selected.pt)，新增联合更新 4 次的选中权重 |
| 动作／外部条件 | routing 唯一 action；任务绑定、任务到达与 map 是外部条件 |
| 训练种子 | 0–49，共 50 个 |
| 验证种子 | 50–54，共 5 个；用于权重选择 |
| 测试种子 | 55–59，共 5 个；本次训练完成后评估，不参与梯度或权重选择 |
| 起点 | frame 9000、18000，即 300、600 秒 |
| 训练预算 | 6 轮，每轮 50 个种子 × 2 个起点 = 100 次更新；合计 600 次更新 |
| 时间课程 | 5／10／30 秒，各 200 次更新；每阶段完整覆盖 100 个窗口两遍 |
| 随机轨迹 | 每个窗口 4 粒子；运动创新时钟固定 30 Hz |
| 优化器 | AdamW，学习率 3e-5；梯度范数上限 2，资源似然系数 0.03 |
| 训练中验证 | 初始基线及每轮结束，即第 100／200／300／400／500／600 次更新；10 秒窗口，全部 5 个验证种子、两个起点 |
| 训练后评估 | 所选权重与初始化成对比较，验证 5 个种子及测试 5 个种子，各自两个起点、每模型 4 粒子，报告 10／30／60 秒指标 |
| 并行 | 原始运行：4 个轨迹采集进程、8 个长期评估进程；优化重启：8 个共享参数工作进程（采集／反传／验证）、16 个长期评估进程，CPU |

保留旧版本源码用于历史检查点兼容；运行时严格核对当前模型类、继承关系与配置，拒绝旧派发头、唤醒／运动先验等可选策略。不得用旧 factual-only 或参数差分训练器替代本次入口。初始化权重有历史预训练谱系，但本次实际执行的网络和优化路径是当前版本。

## 后台运行与恢复

启动器为 [start_joint_50_5_5.py](../../scripts/start_joint_50_5_5.py)。它先审计检查点及全部 60 个源数据，再复制代码和初始化权重，保存 SHA-256、完整参数与命令；tmux 中只使用冻结的源码目录。

```bash
PYTHONPATH=src .venv/bin/python scripts/start_joint_50_5_5.py \
  --output runs/executed_routing_v1/formal_50_5_5_20261115 \
  --session hku_joint_50_5_5
tmux attach -t hku_joint_50_5_5
```

运行目录：[formal_50_5_5_20261115](../../runs/executed_routing_v1/formal_50_5_5_20261115)。`status.json` 是实时阶段，`runtime_audit.json` 证明实际加载的版本，`config.json` 和 `commands.json` 是固定协议。阶段顺序为准备训练锚点、联合训练、验证集 60 秒评估、测试集 60 秒评估；各阶段有独立日志。日志重定向到文件，tmux 窗口安静不代表停止。

真实资源辅助数据按训练种子分片，准备完成一个分片就持久化；训练仅保留一个分片在内存。验证和测试直接读取原始连续轨迹，不生成供优化器使用的图缓存。`anchors/progress.json` 显示已完成种子数，`training/phase.json` 区分初始验证和训练，`training/progress.json`、`training/history.jsonl` 记录更新，`training/resume.pt` 原子保存优化器、随机数和最佳验证权重。中断后确认原 tmux 任务已退出，再用同一启动命令追加 `--resume`，会复用完整分片并恢复训练状态。

本次划分隔离梯度和权重选择。种子 58／59 曾出现在之前的诊断／冒烟测试中，因此不能称作从未查看过的盲测集。数据来自同一 Fab、共享任务到达来源；长期性能与跨拓扑泛化仍需以实际结果判断。训练不会自动替换默认模型。

## 保持训练设计的执行优化

用户要求先验证提速，再从原初始化重新启动完整 600 次更新。原运行目录及其中 `training/resume.pt` 保留。

- `--parallel-replay`：4 条轨迹仍由当前参数生成；独立重放并反传，按粒子原顺序汇总梯度，再加入资源辅助损失，统一裁剪并做一次 AdamW 更新。主进程直接转发采集进程产生的序列化轨迹，避免重复解包／打包。工作进程结束计算之前不会修改参数。
- 每轮全量验证将所有 case × 粒子任务统一排队，按原顺序聚合；种子、起点、粒子数、验证长度和选权标准不变。
- 后续 60 秒成对评估增加工作进程数，按预设随机种子顺序聚合，避免进程完成先后影响求和顺序。
- `--anchor-cache` 可只读复用原始缓存。启动时检查来源清单与 manifest 摘要，读取每份分片时仍校验其 SHA-256；不复制 121GB 缓存，也不改变数据划分。
- 新训练记录增加 `stage_seconds`，分别报告采集、重放反传、资源辅助项及验证耗时；每次更新仍保留原子恢复 checkpoint。

独立实测工具为 `scripts/benchmark_joint_parallel.py`，固定真实训练窗口、4 个随机粒子及初始权重，对比串行／并行梯度、资源辅助项后的裁剪与 AdamW 单步权重，以及更新后的验证结果。结果位于 `runs/executed_routing_v1/speed_equivalence_v2_20261115/result.json`。该基准验证 5 秒窗口，不能用于承诺 10／30 秒阶段或完整 60 秒评估的加速倍数。

优化运行计划目录为 `runs/executed_routing_v1/formal_50_5_5_20261115_fast`，tmux 为 `hku_joint_50_5_5_fast`。初始化与完整训练预算不变，旧运行仅供恢复与审计。

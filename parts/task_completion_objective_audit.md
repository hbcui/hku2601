# Task completion objective audit

The dominant failure was a probability-contract error, amplified by rare-label dilution. The five-way lifecycle decoder represents mutually exclusive outcomes, but the pilot trained and executed class `complete_task` as an independent sigmoid. In a frame with hundreds of live tasks and one completion, averaging per-task binary losses made the positive gradient negligible. Timestamp presence was also repeated as a positive state label after the event, rather than supervising the boundary where the timestamp first appears.

The corrected objective normalizes retain versus complete with a categorical likelihood, balances the positive and negative strata before combining them, and keeps completion as its own loss group instead of averaging it with every resource and queue term. Execution chooses between the same normalized classes. Service phases use a categorical event target. Timestamp heads supervise only newly created timestamps; the ledger writes the exact predicted-boundary time. Training windows are shuffled before sampling so all three training trajectories contribute.

This follows the relevant contracts rather than copying an architecture: DeepFleet trains normalized action probabilities with teacher forcing; Dreamer trains observed sequences and separates dynamics and representation KL; PlaNet's multi-step objective targets informed posteriors. The current repair addresses the local likelihood first. Sequence posterior filtering and a qualified multi-step latent objective remain subsequent work; they cannot repair an incorrectly normalized and nearly zero-weight completion target.
